# ตั้งทรัพย์ในแชทจากโฆษณา Facebook

ระบบรับต้นทางจาก `event.referral`, `message.referral` และ `postback.referral` แล้วตั้งบ้านก่อนสร้างข้อความใน Firestore ซึ่งเป็นตัวกระตุ้นให้บอทตอบ รองรับข้อความจากปุ่ม postback ด้วย

## เริ่มใช้งาน

1. เผยแพร่หน้าแอดมินและ Functions ตามหัวข้อด้านล่าง
2. เปิดห้องแชทของเพจที่ต้องการ ใต้ “ทรัพย์ที่ลูกค้าสนใจ” กด “ผูกโฆษณากับบ้าน”
3. สำหรับเพจเดิม กด “เปิดรับต้นทางจาก Facebook ให้เพจนี้” หนึ่งครั้ง ระบบใช้โทเค็นเพจที่เก็บไว้ฝั่งเซิร์ฟเวอร์ สมัครรับ `messages`, `message_echoes`, `messaging_referrals`, `messaging_postbacks` เพจที่เชื่อมใหม่จะสมัครรับทั้งสี่รายการอัตโนมัติ ตรวจการสมัครรับ Webhook ใน Meta App Dashboard ให้ตรงกันด้วย
4. เลือก “รหัสโฆษณา” ใส่ Ad ID จากตัวจัดการโฆษณา (ไม่ใช่รหัสแคมเปญหรือชุดโฆษณา) แล้วเลือกบ้านที่ยังว่าง กดบันทึก ใช้การจับคู่นี้กับลูกค้าทุกคนของเพจที่มาจากโฆษณาเดียวกัน
5. เมื่อบันทึก ระบบจะผูกบ้านย้อนหลังให้แชทเก่าที่เก็บต้นทางเดียวกันไว้โดยอัตโนมัติ รวมถึงแชทที่เปิดอยู่หากเข้าเงื่อนไข แสดงความคืบหน้าและจำนวนที่ผูก/ข้ามใต้รายการจับคู่ ไม่ส่งข้อความย้อนหลัง ไม่สั่งให้บอทตอบข้อความเก่า และไม่เปิดบอทที่ทีมงานพักไว้
6. ทดสอบด้วยบัญชีลูกค้าจริงที่กดโฆษณาแล้วส่งข้อความ ตรวจรหัสโฆษณาและบ้านที่ตั้งในแชทก่อนเปิดใช้งานวงกว้าง

แต่ละเพจมีรายการจับคู่ได้สูงสุด 200 รายการ แสดงครั้งละ 20 รายการ แก้ไขได้ด้วยการกดรายการที่บันทึกไว้แล้วเลือกบ้านใหม่ การลบรายการไม่ล้างบ้านในแชทเดิม

รองรับรหัสโพสต์และรหัสลิงก์ด้วย โดยจับคู่ตามลำดับ โฆษณา → โพสต์ → ลิงก์ จับคู่รหัสตามที่ Facebook ส่งมา ไม่มีการเดาบ้านจากชื่อโฆษณาหรือราคา หากใช้หลายโฆษณาจากโพสต์เดียวกันและต้องแยกบ้าน ให้ผูก Ad ID ของแต่ละโฆษณา

ลิงก์ที่ผูกบ้านโดยตรงใช้ `https://m.me/PAGE_ID?ref=property_PROPERTY_CODE` เช่น `?ref=property_SPS-TH-1` ระบบตรวจว่ารหัสนี้เป็นทรัพย์ที่ยังว่างจริงก่อนเลือก

## พฤติกรรมที่ต้องทราบ

- รับข้อมูลต้นทางครบทั้งชุดก่อนบันทึกข้อความ ถึงข้อมูลอ้างอิงจะอยู่หลังข้อความหรืออยู่คนละ entry ใน Webhook ชุดเดียวกัน
- ลูกค้าคนเดิมกดโฆษณาบ้านใหม่ จะเปลี่ยนบ้านตามต้นทางล่าสุด ข้อมูลซ้ำหรือเก่าที่ส่งมาล่าช้าไม่ทับต้นทางใหม่หรือการแก้บ้านโดยทีมงาน
- หากมีข้อมูลโฆษณาแต่ยังไม่ผูกบ้าน หรือบ้านขายแล้ว/ถูกลบ บอทจะรอให้ทีมเลือกบ้าน แม้จะปิดโหมดบังคับเลือกทรัพย์ไว้ ป้องกันการตอบด้วยบ้านเก่า
- บ้าน/โน้ต/รูปที่ทีมเคยกรอกในห้องแชทยังเก็บไว้ แต่จะไม่ป้อนข้อมูลบ้านเก่าเหล่านี้ให้บอทขณะใช้บ้านจากโฆษณาอัตโนมัติ
- หากต้นทางเปลี่ยนระหว่างที่โมเดลกำลังเขียน จะไม่ส่งคำตอบที่สร้างจากต้นทางเก่า การอัปเดตบริบทท้ายคำตอบตรวจต้นทางซ้ำใน transaction
- ต้นทางที่มาช้าหลังบอทรอเลือกบ้าน สามารถขอให้ตอบใหม่อัตโนมัติ โดยยังเคารพเวลาอ่านข้อความล่าสุด การตอบของทีมงาน และการพักบอท ไม่ใช้สิทธิ์ข้ามเงื่อนไขแบบปุ่มสั่งตอบของแอดมิน
- การบันทึกหรือแก้ไขคู่โฆษณาจะสร้างงานย้อนหลังใหม่เสมอ ทำครั้งละ 100 แชทและต่อหน้าจนอัตโนมัติครบ งานซ้ำไม่เขียนซ้ำ และการแก้ไข/ลบคู่จับคู่ทำให้งานเวอร์ชันเก่าหยุด
- งานย้อนหลังตรวจต้นทางล่าสุดและลำดับความสำคัญของการจับคู่ใน transaction จึงไม่เปลี่ยนบ้านของคนที่ไปกดโฆษณาอื่นแล้ว ข้ามบ้านที่ทีม/ลูกค้าเลือกไว้ หรือแชทที่มีโน้ต บ้านที่กรอกเอง หรือรูปจากทีมงาน และไม่เลือกบ้านที่ขายแล้ว
- การเห็นโพสต์แล้วเข้าเพจมาทักเองอาจไม่มีข้อมูลต้นทาง ต้องให้ลูกค้าส่งรหัส/ลิงก์บ้านหรือให้ทีมเลือกบ้าน แชทเก่าที่ไม่เคยเก็บต้นทางไม่สามารถรับประกันการจับคู่ย้อนหลัง
- ปุ่ม “เริ่มทดสอบแชทใหม่” ล้างบริบทต้นทางพร้อมบ้านที่จำไว้ ไม่ลบการจับคู่โฆษณาระดับเพจ

## ข้อมูลและสิทธิ์

- การจับคู่เก็บใน `messenger_property_sources` รหัสเอกสารเป็น hash ของเพจ ประเภทต้นทาง และค่าอ้างอิง แยกข้อมูลแต่ละเพจ
- อ่าน/เขียนการจับคู่ผ่าน Admin API ที่ตรวจ Firebase ID token และบทบาทแอดมินเท่านั้น ไม่เปิดสิทธิ์ client โดยตรงและไม่ส่งโทเค็นเพจไปที่หน้าเว็บ ไม่ต้องเพิ่ม Firestore index แบบ composite หรือเปลี่ยน Rules
- ต้นทางล่าสุดเก็บใน `messenger_conversations.facebookReferral`; ต้นทางที่แนบมากับข้อความเก็บในข้อความด้วย
- งานย้อนหลังเก็บใน `messenger_property_backfills` ซึ่ง client ไม่มีสิทธิ์อ่านหรือเขียน ทำงานผ่าน Firestore trigger `facebookPropertySourceBackfill` พร้อม retry เมื่อเกิดข้อผิดพลาดชั่วคราว สถานะรวมเก็บในรายการจับคู่เพื่อให้ Admin API แสดงผล

## เผยแพร่

```sh
npm run build
firebase deploy --only functions:facebookWebhook,functions:facebookMessengerAdmin,functions:facebookAiReply,functions:facebookAiRetry,functions:facebookPropertySourceBackfill,hosting --project sps-property
```

การเผยแพร่โค้ดไม่ได้สร้างข้อมูลจับคู่ให้เอง และต้องเปิดรับต้นทางให้เพจเดิมตามขั้นตอนด้านบน ต้องตรวจด้วยการทักจากโฆษณาจริงเพื่อยืนยันว่าการตั้งค่า Meta และรูปแบบโฆษณาส่งข้อมูลอ้างอิงมาให้แอปนี้
